# Product Overview

## BizDevX Accord（ビズデブエックス・アコード）

ビジネス企画（Working Backwards 型の構想）と AI 駆動開発ライフサイクル（AI-DLC）を組み合わせた **bizdevx 標準プロセス** の進行を、参加者の知見レベルに依存せず一定品質で回すための**プロセスナビゲーター Web アプリ**。

「**今どのステージにいて、誰が何を決めるべきで、次に進む条件は何か**」を管理・指南する。

## プロジェクトの中核思想：BPR

**BPR（思想・文化・視座の変革）はこのプロジェクトの中核**である。本ツールは「これまでのワークフローを単に AI で高速化するツール」ではない。目指す視座転換:

| 従来の視座 | AI ネイティブな視座（本ツールが定着させるもの） |
|-----------|----------------------------------------------|
| 人間が成果物を作り、AI が補助する | AI が成果物を作り、人間は意図の提示・判断・監督に集中する |
| 網羅的な要件・機能を積み上げる | 顧客価値（PRFAQ）を起点に、削ぎ落として最小価値に集中する |
| 技術・体制の制約から発想する | 技術的決定を後ろ倒しし、本質的複雑性にフォーカスする |
| 口頭・会議で決めて記憶に頼る | 質問と決定をファイルに構造化し、文書で意思決定する |
| プロセス遵守が目的化する | プロセス自体を Context に応じてテーラリングし続ける |

## スコープ外（重要な設計判断）

- **LLM は組み込まない（プロセスナビ型）**。AI 作業は利用者の手元ツール（Claude Code / Kiro 等）で実施する。アプリはそのためのカスタマイズ済みプロンプトを配布する
- **成果物の実体は管理しない（リンク＋ステータス管理）**。PRFAQ・ユーザーストーリー・Unit 定義・I/F 契約などの実体は git リポジトリや既存ドキュメント管理に置き、アプリは各成果物への URL リンクとステータスのみを保持する

## コア機能

- **ステージナビ**: YAML テンプレート定義のステージ・チェックリスト・プロンプト集を表示
- **ゲート管理**: 承認必須ゲート（★）と警告型ゲート（⚠）の通過制御と監査証跡
- **トレーサビリティ台帳**: 顧客課題 → ユーザーストーリー → Unit のツリー・孤児検出
- **I/F 契約ボード**: Unit 間インターフェース契約の管理と変更影響可視化
- **ロール別ダッシュボード**: 承認待ちキュー・ゴール乖離サマリ・回帰シグナル
- **監査証跡**: 全ゲート通過・承認操作の記録

## 対象ユーザー（ロール）

| ロール | 責務 |
|--------|------|
| ビジネスオーナー | PRFAQ 承認、スコープ変更承認 |
| プロダクトマネージャー（PM） | PRFAQ 作成主導、ストーリー・機能追加の紐付け管理 |
| ファシリテータ | プロセス全体の健全性監視、プロセス定義のテーラリング |
| アーキテクト/リード | Unit 分割、I/F 契約、技術選定（ADR） |
| Unit 開発者 | 担当 Unit の Construction 実施 |
